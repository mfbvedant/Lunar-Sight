This report is a pedagogical expansion of the original "LunarSight" document, keeping the
same seven-chapter structure but explaining each concept in more detail and in more student-
friendly language.[^1] It focuses on how the five agents and the LangGraph orchestration work
together to detect lunar subsurface ice in the South Pole region and plan safe rover traverses.
Each chapter has two layers:
A detailed technical explanation (for deep understanding and implementation).
A short "How to understand it" section written in simpler terms for quick intuition.
Where appropriate, suggested diagrams and external links to simulations or learning resources
are included so the architecture can be studied and prototyped.
Agent 1 is the "data engineer" of the LunarSight system. Its job is to fetch raw orbital radar data
and elevation models, align them precisely in a common coordinate system, and derive slope
and aspect maps needed by downstream physics and path-planning agents.[^1]
Data sources and APIs
ISRO Science Data Archive (ISDA) via the PRADAN portal provides Chandrayaan-2 DFSAR
data in PDS4 format (L-band and S-band complex radar swaths).
NASA Planetary Data System (PDS) LOLA Data Node provides global lunar elevation data
with ~10 cm vertical precision and ~1 m absolute accuracy at high latitudes.[^1]
Agent 1 authenticates to both APIs, queries data using a bounding box (e.g., Faustini Crater
coordinates), and downloads the relevant .img and .tif files to local NVMe storage for high-
throughput processing.[^1]
Geospatial processing stack
GDAL + Rasterio: for reading, warping, and reprojecting multi-gigabyte raster arrays.
NumPy/SciPy: for vectorized numeric operations on elevation and radar grids.
PDS4 client libraries: for parsing XML labels that describe radar products (dimensions,
scaling, polarization channels, etc.).[^1]

Complex-valued neural architecture
Works on complex tensors (real + imaginary parts) instead of just amplitude.
Uses complex convolutions, complex activation functions (e.g., Complex-ReLU), and

Agent 3 turns the cleaned radar signal into physical labels:
It figures out how much of the signal comes from flat ground, rough rocks, or ice hidden in

It uses math to color-code every pixel into "rock-like", "ice-like", or "regolith-like".

Agent 4 is the main AI "vision" agent. It consumes the Polarimetric Feature Tensor from Agent 3

Because there is no dense ground truth drilling data in permanently shadowed regions, Agent 4

Chapter 4 – Agent 4: Weakly-Supervised Semantic Segmentation
Technical explanation
Ice seeds (label 1) only where L-band CPR > 1, S-band CPR > 1, and DOP < 0.13.
Rock seeds (label 0) in sunlit equatorial pixels with strong odd-bounce (bare regolith).
Most pixels remain unlabeled (NaN), representing ambiguous territory.
[^1]
During training, U-Net learns to expand from these sparse seeds to dense masks using
contextual information in the multi-channel tensor (intensity, slope, m-χ features) via weakly
supervised strategies such as CRFs and self-training.[^1]
Internal flow of Agent 4
1. Read Polarimetric Feature Tensor (Agent 3) and DEM/slope tensor (Agent 1) from state.
2. Run heuristic mask generator to produce sparse ice/rock seeds using CPR and DOP
thresholds.
3. Initialize U-Net model via SMP with pre-trained encoder.
4. Fine-tune on sparse labels, learning polarimetric and topographic textures.
5. After convergence, run forward inference to produce a full Binary Ice Mask and confidence
map.
6. Write mask and confidence map to state as the geological target for Agent 5.
[^1]

Agent 5 is the agent that asks: "Can the rover actually drive there and survive?"
It uses physics of soil and wheel traction to avoid slopes the rover cannot climb.
It keeps track of battery and heat while planning the path.

Agents 1–5 are powerful specialists but must be coordinated by an orchestration layer that
handles state, sequencing, and error recovery. LunarSight uses LangGraph to model the system
as a stateful multi-agent application with cyclical workflows.
StateGraph architecture
1. State schema (TypedDict)
Central JSON-like object holds shared context: file paths (e.g., raw_data_path,
c2_matrix_path), status flags (agent1_status, path_failure), rover constraints (max
slope, battery), etc.
Agents pass lightweight references (file paths, metadata) instead of huge tensors to
avoid memory fragmentation.[^1]
2. Nodes
Agents 1–5 implemented as Python functions that:
Read needed context from state.
Perform their specialized computation.
Write outputs and status codes back to state.
Each node is a vertex in the LangGraph StateGraph.[^1]
3. Edges and conditional routing
Edges encode workflow transitions.
A central Supervisor node reads state, decides which agent to run next, and handles
failures by routing backwards when needed.
Crucially, LangGraph allows cycles, enabling iterative refinement and conflict
resolution.
[^1]

Technical explanation

Phase 2: Radar analysis
Agent 1 completes and updates state.

Phase 3: Segmentation and routing
Supervisor triggers Agent 4 to generate Binary Ice Mask.

Cyclical conflict resolution example
If Agent 5 reports path_failure (no safe route due to terramechanics constraints):
Supervisor reads the flag and routes back to Agent 4 via a conditional edge.
State is modified to relax confidence thresholds or select alternative shallower ice deposits.
Agent 4 recomputes map; Agent 5 tries routing again.
[^1]
This closed-loop cycle continues until a feasible solution or global failure condition is reached,
embodying resilient multi-agent behavior.

The original hackathon proposal had strong high-level ideas but several critical weaknesses:
fabricated mathematics, vague metrics, and missing physical detail. This chapter outlines a
blueprint to turn LunarSight into a mission-ready architecture.[^1]
1. Remove fabricated math; enforce scientific rigor
Issues:
Arbitrary equations (e.g., made-up polynomials, fake kinetic energy formulas) not
grounded in any radar or orbital physics.[^1]
Non-standard units (e.g., sbps, mprs, mpes) instead of real engineering metrics.
Actions:
Completely remove all hallucinated equations from documentation and code.
Use only physically correct formulas from Chapters 3 and 5 (Raney’s m-χ, Mohr–Coulomb,
Janosi–Hanamoto).
Replace fictional metrics with standardized ones: MB/s for data throughput, TFLOPS for
compute, ms for latency.[^1]
2. Exploit decentralized GPU economics
Training CV-CNN (Agent 2) and U-Net (Agent 4) on full-resolution DFSAR swaths requires high
VRAM (80 GB for H100/A100). Hyperscalers such as AWS are expensive; decentralized GPU
marketplaces like Vast.ai or Spheron can significantly reduce costs.[^1]
