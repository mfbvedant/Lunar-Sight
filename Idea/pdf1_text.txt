 
LunarSight: A Multi-Agent Software 
Architecture for Lunar Subsurface Ice 
Detection and Autonomous Traverse 
Planning 
The transition from orbital remote sensing to sustained in-situ resource utilization (ISRU) on the 
lunar surface requires a paradigm shift in how planetary data is processed, synthesized, and 
operationalized. Historically, lunar radar astronomy relied on Earth-based observations from 
facilities like the Arecibo Observatory or single-frequency orbital instruments such as the 
Mini-RF on the Lunar Reconnaissance Orbiter (LRO) and Chandrayaan-1. These legacy 
systems predominantly operated in the S-band (12 cm wavelength) utilizing a 
hybrid-polarimetric architecture, which, while effective for surficial characterization, severely 
limited subsurface penetration. 
The introduction of the Chandrayaan-2 Dual Frequency Synthetic Aperture Radar (DFSAR) 
instrument represents a quantum leap in microwave imaging. By operating simultaneously in 
both the L-band (24 cm wavelength) and the S-band, DFSAR offers the first fully polarimetric 
(quad-pol) observations of the Moon from orbit. The longer L-band wavelength penetrates 
several meters into the cryogenic regolith, allowing for the differentiation between thin surficial 
frost layers and massive, deeply buried volumetric ice slabs. However, isolating these volatile 
signatures within the doubly shadowed terrain of the South Polar Regions—such as the extreme 
environment of the Faustini Crater—demands multi-modal data synthesis, complex radar 
polarimetry, and kinodynamically aware pathfinding. 
To address these monumental computational challenges, the "LunarSight" architecture operates 
as a sophisticated, five-agent artificial intelligence ecosystem. By synthesizing DFSAR data with 
high-resolution topographic models, the system autonomously isolates volumetric ice signatures 
and routes rovers through extreme cryogenic terrain. This report provides an exhaustive, 
seven-chapter technical deconstruction of the LunarSight system, detailing the theoretical 
foundations, technological stacks, internal operational flows, orchestration methodologies, and 
strategic blueprints required to scale this architecture into a mission-ready deployment. 
Chapter 1: Agent 1 - The Data Ingestion and 
Topographic Synthesis Agent 
The foundational layer of the LunarSight architecture relies on the precise acquisition, spatial 
alignment, and mathematical synthesis of orbital data. Agent 1 is explicitly designed to interface 
with planetary data archives, extracting raw microwave and altimetry arrays, and generating the 
baseline geospatial tensors required by all downstream analytical agents. Without a 
geometrically flawless ingestion pipeline, subsequent deep learning and polarimetric 
calculations will suffer from severe spatial misalignment, rendering autonomous navigation 
impossible. 
 
Pipeline and Technological Stack 
Agent 1 functions as an automated spatial data engineering pipeline. It requires programmatic, 
API-driven access to the ISRO Science Data Archive (ISDA) via the PRADAN (Policy Based 
Data Retrieval, Analytics, Dissemination and Notification) portal. This portal serves as the 
primary repository for Chandrayaan-2 data, housing the PDS4-compliant DFSAR imagery. The 
agent specifically targets the L-band and S-band complex radar swathes, prioritizing data 
collected over the permanently shadowed regions of the lunar South Pole. 
Simultaneously, the agent interfaces with the NASA Planetary Data System (PDS) LOLA Data 
Node. The Lunar Orbiter Laser Altimeter (LOLA) provides global topographic mapping with a 
vertical precision of approximately 10 centimeters and an accuracy of 1 meter. For high-latitude 
operations poleward of 60^\circ, LOLA produces the most accurate polar terrain models 
available, providing the necessary geodetic framework to control the radar data. 
The primary technological stack driving Agent 1 includes the Geospatial Data Abstraction 
Library (GDAL) and its Python binding, Rasterio. These are industry-standard C/C++ libraries 
capable of warping, projecting, and reading massive multi-gigabyte spatial raster arrays in 
memory-efficient blocks. NumPy and SciPy are heavily utilized for vectorized matrix 
transformations and array manipulation, while custom PDS4 client libraries are deployed to 
parse the complex XML labels inherent to the international standard for planetary science data 
archiving. 
Topographic Synthesis and Horn's Algorithm 
Raw elevation data, while valuable, is insufficient for direct rover navigation; it must be 
converted into deterministic slope gradients. Agent 1 is programmed to compute localized slope 
using Horn's algorithm, a mathematically robust estimator that evaluates a 3 \times 3 moving 
window across the Digital Elevation Model. 
The algorithm calculates the east-west gradient (\frac{dz}{dx}) and the north-south gradient 
(\frac{dz}{dy}) using finite difference approximations. The east-west gradient describes how 
elevation changes between the east and west sides of the pixel neighborhood, weighted heavily 
toward the central row : 
∂z/∂x = ((z_{i+1, j-1} + 2z_{i+1, j} + z_{i+1, j+1}) - (z_{i-1, j-1} + 2z_{i-1, j} + z_{i-1, j+1})) / 8Δx 
Similarly, the north-south gradient describes elevation changes across the vertical axis : 
∂z/∂y = ((z_{i-1, j+1} + 2z_{i, j+1} + z_{i+1, j+1}) - (z_{i-1, j-1} + 2z_{i, j-1} + z_{i+1, j-1})) / 8Δy 
The overall surface slope angle (\theta) is then derived by combining these gradients : 
Slope (θ) = arctan(√((∂z/∂x)² + (∂z/∂y)²)) 
Furthermore, the aspect (the compass direction that the slope faces) is calculated using the 
arctangent of the two gradients, providing critical azimuth data for the rover's solar panel 
orientation. By integrating Horn's method natively into the data pipeline, Agent 1 ensures that 
downstream terramechanics agents receive highly accurate, mathematically smoothed gradient 
tensors. This method is vastly superior to simpler algorithms (such as Zevenbergen-Thorne or 
unweighted nearest-neighbor models) for highly cratered lunar terrains, as the weighted 3 \times 
3 window effectively suppresses high-frequency noise and artificial stepping anomalies inherent 
in laser altimetry. 
Internal Operational Flow 
 
The internal execution architecture of Agent 1 follows a strict, step-by-step sequential flow 
designed for autonomous fault tolerance. 
The initiation phase is triggered by a geospatial bounding box passed via the system's global 
state object, defining the target latitude and longitude parameters (e.g., the coordinates for the 
Faustini Crater at roughly 87.3^\circ S, 77^\circ E). Upon receiving these coordinates, the agent 
authenticates with the ISDA PRADAN and NASA PDS APIs, querying the databases for 
available radar and elevation datasets intersecting the bounding box. 
During the execution phase, the agent downloads the relevant PDS4 .img and .tif data products 
into localized, high-speed NVMe storage to prevent I/O bottlenecks. Utilizing GDAL, the agent 
reprojects all spatial arrays into a unified lunar polar stereographic coordinate reference system, 
referenced to a 1737.4 kilometer lunar sphere, ensuring that a pixel in the radar array perfectly 
aligns with the same physical square meter in the topographic array. The LOLA DEM is then 
processed through the vectorized Horn's algorithm to generate the discrete slope and aspect 
arrays. 
In the final output phase, the agent writes a highly co-registered, multi-channel spatial tensor to 
the system's shared memory. This tensor contains the raw S-band complex data, L-band 
complex data, LOLA elevation data, and Horn-derived slope gradients. The agent concludes its 
operation by updating the global state with a status flag indicating ingestion success, thereby 
signaling the orchestration layer to proceed.

Chapter 2: Agent 2 - The Complex-Valued SAR 
Despeckling Agent 
Synthetic Aperture Radar imaging is inherently corrupted by speckle. This spatial degradation is 
not additive noise, but rather a spatially correlated, signal-dependent multiplicative noise 
originating from the constructive and destructive interference of coherent backscatter generated 
by sub-resolution scatterers within each pixel footprint. Agent 2 is a dedicated, highly 
specialized computer vision model engineered to mathematically strip this interference from the 
DFSAR data without compromising the foundational physics required for downstream 
polarimetric decomposition. 
Pipeline and Technological Stack 
The standard multiplicative model for SAR speckle is expressed as Y = F \cdot X, where Y is the 
observed noisy intensity, X is the underlying noise-free radar cross-section, and F represents 
 
the normalized fading speckle random variable. Historically, the mitigation of speckle relied on 
multilook integration and spatial filtering techniques, such as the Lee, Frost, Refined Lee, and 
Gamma-MAP filters. These classical filters operate by calculating local statistics within a moving 
window. While computationally trivial, they introduce severe systemic flaws into high-resolution 
planetary workflows: they aggressively blur sharp topographic edges, smooth over fine 
structural textures, and, most critically, frequently destroy the relative polarimetric phase 
information required for calculating Stokes parameters. 
To circumvent these limitations, Agent 2 pivots toward the vanguard of modern radar processing 
by utilizing a Complex-Valued Convolutional Neural Network (CV-CNN) designed as a denoising 
autoencoder. Standard Real-Valued (RV) neural networks process only the amplitude (intensity) 
of the radar returns, permanently discarding the complex phase. In stark contrast, CV-CNNs 
utilize specialized complex convolutional layers, complex activation functions (such as 
Complex-ReLU or Complex-Sigmoid), and complex batch normalization protocols. This 
architecture inherently preserves the complete phase matrix of the electromagnetic wave, a 
requirement for fully polarimetric analysis. 
The technological backbone for Agent 2 is PyTorch, specifically augmented by libraries such as 
ComplexPyTorch and cvnn. Since PyTorch version 1.7, the framework natively supports the 
torch.complex64 datatype, allowing tensors to maintain distinct real and imaginary components 
throughout the forward pass and backpropagation processes, facilitating the calculation of 
complex gradients. The NVIDIA CUDA ecosystem is heavily relied upon to accelerate these 
computationally intense floating-point operations. 
Complex Covariance Matrix Preservation 
The Chandrayaan-2 DFSAR instrument operates in both fully polarimetric (quad-pol) and 
compact polarimetric modes, transmitting and receiving varying combinations of electromagnetic 
polarizations (e.g., Horizontal-Horizontal, Horizontal-Vertical). The backscattered signal 
measured by the antenna is represented mathematically by a complex scattering matrix. 
Because the lunar surface consists of distributed scatterers (regolith, rocks, ice), this scattering 
matrix is statistically transformed into a positive semi-definite complex covariance matrix (C_2 
for dual-pol, or C_3 for quad-pol). 
For a dual-polarization system, the 2 \times 2 covariance matrix C_2 is defined by the following 
expectation values: 
C₂ = [ ⟨|E_{HH}|²⟩  ⟨E_{HH} E_{HV}*⟩ ; ⟨E_{HV} E_{HH}*⟩  ⟨|E_{HV}|²⟩ ] 
The diagonal elements of the C_2 matrix represent the real-valued intensity of the radar 
backscatter for each specific polarization. Crucially, the off-diagonal elements encode the 
complex cross-covariance terms, capturing the critical phase correlation properties 
(\phi_{HH-HV}) between the channels. 
Agent 2's CV-CNN autoencoder is engineered to map the noisy complex covariance matrix to a 
clean, idealized target matrix. By minimizing a complex-aware loss function, the network isolates 
the multiplicative speckle distribution and strips it away. Because the convolutions operate in the 
complex domain, the integrity of the complex conjugates in the off-diagonal elements is perfectly 
maintained. 
Internal Operational Flow 
The operational sequence of Agent 2 is computationally intensive, transforming raw geospatial 
data into pristine physical matrices. 
 
The initiation phase begins when the agent reads the state object to locate the co-registered 
raw L-band and S-band complex arrays generated by Agent 1. Upon confirming the integrity of 
the files, the agent initializes the CV-CNN architecture in PyTorch, loading pre-trained weights 
optimized for radar cross-section extraction, and moves the model parameters onto the 
available cloud GPU architecture (e.g., an NVIDIA H100 or A100). 
Execution commences by mathematically transforming the raw multi-look complex data into the 
corresponding C_2 and C_3 covariance matrices for both the L-band and S-band frequencies. 
These matrices are converted into torch.complex64 tensors and fed into the CV-CNN. The 
network passes the tensors through successive complex 2D and 3D convolutions, extracting 
high-dimensional latent features that represent the underlying lunar topology, while 
systematically filtering out the multiplicative noise distribution in the complex domain. 
The output phase produces a mathematically pristine, noise-free complex covariance tensor. 
The agent verifies that the polarimetric phase relationships between the transmit and receive 
channels remain intact, serializes the clean tensor to disk, and updates the global graph state to 
trigger the feature extraction processes.

Chapter 3: Agent 3 - The Polarimetric Feature 
Extraction Agent 
With the speckle interference surgically removed, the data exists as a pristine, complex 
mathematical representation of the radar echo. However, this raw covariance matrix is not 
directly actionable by computer vision segmentation models. Agent 3 serves as a deterministic 
physics engine, translating the complex electrical field measurements into distinct physical 
geological indicators, calculating the specific polarimetric decompositions required to 
differentiate between jagged surface roughness and volumetric subsurface water-ice. 
Pipeline and Technological Stack 
In contrast to the neural networks utilized in Agents 2 and 4, Agent 3 relies entirely on rigid 
mathematical formalisms. It utilizes the Python NumPy and SciPy libraries to perform highly 
parallelized, pixel-wise algebraic calculations across the massive despeckled covariance 
matrices. The agent's logic is fundamentally built upon the established principles of planetary 
 
radar polarimetry and the Stokes vector space. 
Stokes Parameters and the Circular Polarization Ratio 
To fully characterize the partially polarized electromagnetic backscatter observed by the 
Chandrayaan-2 DFSAR instrument, Agent 3 must first derive the four Stokes parameters (S_1, 
S_2, S_3, S_4). Assuming a circular transmission basis (which is standard for 
hybrid-polarimetric architectures operating on the Moon), these parameters define the total 
power and the polarization state of the wave. From the complex covariance matrix, the Stokes 
parameters are calculated as: 
S₁ = ⟨|E_H|²⟩ + ⟨|E_V|²⟩, S₂ = ⟨|E_H|²⟩ - ⟨|E_V|²⟩, S₃ = 2 Re⟨E_H E_V*⟩, S₄ = -2 Im⟨E_H E_V*⟩ 
Here, S_1 represents the total backscattered power, while S_2, S_3, and S_4 describe the 
polarization ellipse. From these fundamental vectors, the agent calculates the Circular 
Polarization Ratio (CPR), which is the primary diagnostic tool historically used for isolating ice 
signatures in planetary science. In a circular basis, CPR is defined as the ratio of the 
same-sense circular polarization to the opposite-sense circular polarization: 
CPR = (S₁ - S₄) / (S₁ + S₄) 
High CPR (values generally greater than 1) is strongly associated with the volume scattering 
inherent to water-ice trapped within a cryogenic regolith matrix. However, radar astronomy is 
plagued by a fundamental ambiguity: high CPR is also generated by wavelength-scale surface 
roughness, such as blocky impact ejecta and jagged rocks that induce dihedral (double-bounce) 
reflections. 
The m-chi Decomposition 
To resolve the ambiguity between rock and ice, Agent 3 executes the m-\chi (m-chi) 
decomposition, a compact polarimetric technique pioneered by R. Keith Raney. The m-\chi 
decomposition maps the Stokes parameters onto the Poincaré sphere, characterizing the field 
using two key variables: the Degree of Polarization (m) and the Poincaré ellipticity parameter 
(\chi). 
The Degree of Polarization, which measures the portion of the electromagnetic wave that 
remains polarized after interacting with the lunar surface, is calculated as : 
m = √(S₂² + S₃² + S₄²) / S₁ 
The ellipticity parameter \chi, which determines whether the bounce is odd or even, is derived 
through the relationship : 
sin(2χ) = -S₄ / (m S₁) 
Agent 3 utilizes these variables to decompose the total backscatter into three distinct physical 
scattering mechanisms, mapping them into a Red-Green-Blue (RGB) color space for 
downstream tensor ingestion : 
●​ Red (Even/Double-Bounce Scattering): R = √((m S₁ (1 + sin 2χ)) / 2) 
●​ Green (Random/Volumetric Scattering): G = √(S₁ (1 - m)) 
●​ Blue (Odd/Surface Scattering): B = √((m S₁ (1 - sin 2χ)) / 2) 
By breaking down the signal mathematically, the agent provides a multi-dimensional physical 
feature space that allows subsequent AI models to definitively distinguish between a rough, 
rocky crater wall (dominated by the Red double-bounce component) and an ancient, deeply 
buried ice slab (dominated by the Green volumetric scattering component). 
 
Internal Operational Flow 
The operation of Agent 3 is deterministic, ensuring absolute mathematical consistency across 
the dataset. 
Initiation occurs when the agent receives the file pointers for the clean L-band and S-band C_2 
covariance tensors generated by Agent 2. 
Execution proceeds through highly optimized, vectorized array operations. The agent steps 
through the data, calculating the S_1 through S_4 Stokes parameters for both the L-band and 
S-band frequencies. It subsequently computes the L-band CPR, the S-band CPR, the Degree of 
Polarization (m), and the three isolated m-\chi components (Odd, Even, Volume). Furthermore, 
the agent integrates the recent empirical findings of Sinha et al. (2026), flagging pixels that meet 
the strict physical threshold for doubly shadowed crater ice: CPR greater than 1 coupled with a 
Degree of Polarization strictly lower than 0.13. 
The output phase consolidates these calculations. The agent generates a dense, 
mathematically deterministic "Polarimetric Feature Tensor." This multi-layered array stacks the 
CPR, m, and m-\chi scattering mechanisms, providing the ultimate physical dataset ready for 
machine learning segmentation.

Chapter 4: Agent 4 - The Weakly-Supervised Semantic 
Segmentation Agent 
Agent 4 represents the core analytical intelligence of the LunarSight framework. Its mandate is 
to ingest the multi-channel polarimetric feature tensor generated by Agent 3, synthesize it with 
the topographic data from Agent 1, and output a highly accurate, binary classification map 
indicating the precise geospatial boundaries of subsurface ice deposits versus barren lunar 
rock. 
Pipeline and Technological Stack 
In terrestrial remote sensing, fully supervised semantic segmentation requires tens of thousands 
of dense, pixel-perfect ground truth masks. However, in lunar exploration, there is an absolute 
absence of in-situ physical drilling data within the Permanently Shadowed Regions of the South 
Pole. Because exact pixel-level ground truth for volumetric ice simply does not exist, training a 
traditional supervised model is impossible. Agent 4 circumvents this insurmountable obstacle by 
employing a Weakly-Supervised Cross-Modal Learning paradigm. 
 
The agent utilizes the Segmentation Models PyTorch (SMP) library, a highly modular 
framework that decouples the network architecture from the feature extractor (encoder). This 
modularity allows developers to rapidly swap configurations based on performance. Agent 4 
deploys a classic U-Net architecture—renowned for its spatial precision in biomedical and 
remote sensing applications due to its symmetric encoder-decoder structure and skip 
connections—backed by an encoder (such as EfficientNet or ResNet) that has been pre-trained 
on massive terrestrial datasets like ImageNet. This transfer learning approach allows the 
network to rapidly converge on the generalized textures and topological features of lunar impact 
craters without requiring a massive dataset trained from scratch. 
Weak Supervision and Physical Priors 
Weakly-supervised segmentation reduces the labeling burden by replacing dense, hand-drawn 
masks with coarse, incomplete, or algorithmically generated "pseudo-labels". In this 
architecture, sparse pseudo-labels are algorithmically generated using the rigid physical priors 
calculated by Agent 3. 
Relying on the empirical diagnostic criteria established by Sinha et al. (2026), the agent's logic 
hardcodes definitive "ice seeds" only at pixels that satisfy three extreme conditions 
simultaneously : 
1.​ L-band CPR > 1 (Indicating deep volume scattering or extreme roughness). 
2.​ S-band CPR > 1 (Indicating shallow volume scattering or surface roughness). 
3.​ Degree of Polarization (DOP) < 0.13 (Crucially filtering out the spurious dihedral returns 
from blocky rocks). 
Pixels meeting these rigorous physical criteria are marked as a definitive 1 (Ice). Conversely, 
sunlit equatorial pixels exhibiting high m-\chi odd-bounce characteristics (indicating bare 
regolith) are marked as a definitive 0 (Rock). The vast majority of the crater surface, which 
remains ambiguous, is left unlabeled as a NaN value. 
During the training cycle, the U-Net acts as a highly advanced spatial interpolator. By analyzing 
the contextual multi-modal tensor (intensity, topographic slope, m-\chi components) surrounding 
the sparse seeds, the network learns the latent polarimetric textures of genuine ice. Through 
mechanisms like Conditional Random Fields (CRFs) or iterative self-training, the network 
confidently generates dense predictions across the ambiguous boundary regions, effectively 
expanding the sparse pseudo-labels into a complete, dense semantic mask covering the entire 
crater floor. 
Internal Operational Flow 
The internal operation of Agent 4 bridges the gap between physics and computer vision. 
The initiation phase begins when the agent loads both the Polarimetric Feature Tensor (from 
Agent 3) and the LOLA DEM/Slope tensor (from Agent 1). 
During execution, the agent first runs a heuristic mask generator. This script applies the CPR > 
1 and DOP < 0.13 logic across the tensor to create the sparse training seeds. The SMP U-Net 
model is then initialized with its ImageNet pre-trained weights. The model is fine-tuned 
iteratively, learning to correlate the sparse ice/rock labels with the broader radar cross-sections. 
Once the cross-entropy loss function converges, the network performs a final forward inference 
pass over the entire Faustini Crater dataset. 
In the output phase, the agent produces a "Binary Ice Mask" (a highly detailed spatial grid 
designating the exact Ice vs. Rock boundaries). Accompanying this mask is a probabilistic 
 
confidence map, serving as the ultimate geological target destination for the autonomous rover.

Chapter 5: Agent 5 - The Terramechanic-Aware 
Spatiotemporal Pathfinding Agent 
The isolation and detection of subsurface ice hold no practical value unless an autonomous 
robotic platform can safely navigate the lunar topography to extract it. The Faustini Crater 
presents a highly extreme operational environment; the crater spans 41 kilometers in diameter, 
characterized by steep crater walls with median slopes exceeding 12.3^\circ, leading down to 
heavily cratered, cryogenic lower floor units exhibiting mass wasting and temperatures 
stabilizing near 25\text{K}. Agent 5 is explicitly tasked with routing the rover from the illuminated 
crater rim down into the shadowed ice reserves identified by Agent 4, avoiding total mission 
failure. 
Pipeline and Technological Stack 
Standard geometric pathfinding algorithms—such as basic Dijkstra or static A* operating on a 
rigid grid—are entirely insufficient for planetary robotics. If an algorithm penalizes a 15^\circ 
slope but ultimately commands the rover to traverse it because alternative routes are 
mathematically longer, the vehicle will experience catastrophic failure, as standard wheeled 
rovers (like ISRO's Pragyan) possess strict slope climbing limits bounded near 10^\circ. 
To overcome this, Agent 5 employs a highly customized Spatiotemporal Kinodynamic A 
Algorithm*, implemented via Python's SciPy.spatial and advanced graph-theory network routing 
libraries. This planner does not simply look at geometry; it integrates live physical models of soil 
failure and tracking moving solar illumination. 
Terramechanics: Slip, Sinkage, and Soil Failure 
The most glaring omission in conceptual navigation frameworks is the lack of terramechanical 
modeling. The lunar surface is covered in unconsolidated, fine-grained regolith. When a 
wheeled vehicle attempts to ascend a slope, the soil yields, causing severe longitudinal slip and 
lateral sinkage. A pure geometric analysis is insufficient; Agent 5 calculates a slip-aware cost 
function g(n) based on classical terramechanics. 
The interaction between the rover wheel and the regolith is governed by the Mohr-Coulomb 
 
Failure Criterion, which dictates the maximum shear stress (\tau_{max}) the soil can withstand 
before catastrophic failure occurs : 
τ_{max} = c + σ tan ϕ 
Where c represents the soil cohesion, \sigma is the applied normal stress from the rover's mass, 
and \phi is the internal friction angle of the regolith (approximately 30^\circ to 35^\circ for lunar 
soil). 
As the wheel turns, the actual shear stress (\tau) generated as it slips through the regolith is 
modeled by the Janosi-Hanamoto equation : 
τ(j) = (c + σ tan ϕ)(1 - e^{-j/K}) 
Where j is the soil shear displacement (driven by wheel slip) and K is the shear-deformation 
modulus. 
By integrating these equations across the wheel contact patch, Agent 5 predicts the gross 
tractive effort and precise drawbar pull of the rover based on the localized Horn's slope 
derivative (provided by Agent 1). If the slope angle approaches the friction angle of the soil, the 
required tractive force to climb the slope will exceed \tau_{max}, resulting in 100% slip and 
complete immobilization. When this threshold is breached, Agent 5 mathematically registers the 
terrain as an infinitely costly, impenetrable obstacle, refusing to plot a route regardless of 
distance. 
Spatiotemporal Illumination Constraints 
Beyond slip, a solar-powered rover cannot simply drive into a Permanently Shadowed Region 
(PSR) without tracking its battery capacitance and internal thermal limits. The Moon's synodic 
period lasts approximately 708 hours, creating slow-moving, high-contrast shadows. 
Agent 5 models the search space in four dimensions (x, y, \theta, t). The spatiotemporal A* 
search tracks the moving sun vector across the LOLA DEM. The heuristic function h(n) 
dynamically manages a virtual thermal and electrical battery, ensuring that the path 
length—adjusted for the slower velocity caused by terramechanical slip—guarantees the rover 
can physically reach the ice deposit and return to the sunlit rim before critical thermal depletion 
occurs in the 25\text{K} environment. 
Internal Operational Flow 
Agent 5 operates as the final arbitrator of mission safety, transforming semantic maps into 
actionable driving commands. 
Initiation is triggered when Agent 5 receives the Binary Ice Mask (from Agent 4) marking the 
target destination, alongside the LOLA DEM and Horn's Slope array (from Agent 1) providing 
the environmental map. 
Execution begins by discretizing the map into a searchable graph. The agent expands nodes 
iteratively using the A* formula f(n) = g(n) + h(n). The cost function g(n) dynamically evaluates 
every adjacent pixel, applying the Janosi-Hanamoto and Mohr-Coulomb equations to calculate 
the expected wheel slip based on the specific mass and suspension type of the deployed rover 
(e.g., a 6-wheel rocker-bogie vs. a 4-wheel active suspension). Simultaneously, the heuristic 
h(n) evaluates the remaining distance, heavily weighing it against the spatiotemporal movement 
of lunar shadows to prevent thermal death. 
The output phase generates a final, optimal, kinodynamically safe, and thermally viable rover 
driving traverse. This output is structured as a matrix of geographic coordinates, expected 
temporal waypoints, and anticipated slip ratios, ready for ingestion by the rover's local mobility 
 
controller.

Chapter 6: Unified Multi-Agent Orchestration via 
LangGraph 
While Agents 1 through 5 represent highly specialized, incredibly powerful analytical silos, a 
planetary software architecture requires a robust orchestration layer. This layer must manage 
vast data flows, trigger sequential execution, handle fault tolerance, and manage complex state 
handoffs. To achieve this level of system cohesion, the LunarSight architecture employs 
LangGraph, a framework explicitly designed for building resilient, stateful multi-agent 
applications utilizing graph-based state machines. 
Architectural Paradigm: The StateGraph 
Traditional Directed Acyclic Graph (DAG) executors force data through rigid, one-way pipelines. 
In contrast, LangGraph permits cyclical workflows, which are absolutely critical for error 
recovery, iterative refinement, and autonomous conflict resolution. The entire LunarSight system 
is modeled as a StateGraph, consisting of three core interconnected components: 
1.​ State Schema (TypedDict): At the center of multi-agent design is context engineering. 
The system relies on a strictly typed, centralized JSON-like state object that represents 
the shared memory of the entire application. This state dictionary contains keys for data 
paths (e.g., raw_data_path, c2_matrix_path), process status flags (agent_1_status), 
system constraints (rover_max_slope, thermal_battery_limit), and execution metadata. 
Crucially, instead of passing massive gigabyte-scale tensors directly through 
memory—which would cause immediate memory fragmentation—the agents pass 
lightweight file pointers and metadata via the state object, enabling highly efficient 
handoffs. 
2.​ Nodes: Agents 1 through 5 are encapsulated as individual Python functions (nodes) 
within the graph. When triggered, a node extracts its necessary context from the State, 
performs its specialized task (e.g., CV-CNN despeckling or A* pathfinding), and writes the 
output paths and status codes back to the State. 
3.​ Edges and Conditional Routing: Edges define the control flow rules between nodes. 
LunarSight utilizes dynamic conditional edges driven by a central "Supervisor Agent" (a 
lightweight routing logic block that coordinates the specialized agents). 
 
The Orchestration Flow and Cyclical Conflict Resolution 
The orchestration operates under a deterministic Supervisor-Worker pattern. 
Phase 1 (Preparation): The workflow is initialized when a human operator injects mission 
parameters (e.g., target crater coordinates, rover kinematic limits) into the StateGraph. The 
Supervisor activates Agent 1. Upon completion of downloading and topographic synthesis, 
Agent 1 updates the state with the paths to the synthesized DEM and raw radar arrays. 
Phase 2 (Radar Analysis): The Supervisor detects the completion of Agent 1 and triggers 
Agent 2. Agent 2 despeckles the complex data, serializes it, and updates the state. The 
Supervisor then routes to Agent 3, which executes the m-\chi physics calculations, subsequently 
returning the feature tensor pointers to the state object. 
Phase 3 (Segmentation and Routing): Agent 4 is triggered, reading the physical tensors and 
generating the binary ice mask. The state is updated, providing the final destination coordinates 
for Agent 5, which then executes the terramechanical pathfinding algorithm. 
Cyclical Conflict Resolution: LangGraph's cyclical design enables systemic resilience, 
preventing the architecture from collapsing upon encountering physical impossibilities. For 
example, if Agent 5 calculates that no safe path exists into the target ice deposit due to severe 
wheel slip constraints (i.e., the required Janosi-Hanamoto shear stress exceeds the 
Mohr-Coulomb soil failure limit across all routes), it updates the state with a path_failure flag. 
The Supervisor intercepts this flag and utilizes a conditional edge to route the workflow 
backwards to Agent 4. The Supervisor manipulates the state to instruct Agent 4 to lower its 
confidence threshold or select a secondary, shallower ice deposit that may be more accessible. 
Agent 4 generates a new map, and Agent 5 attempts routing again. This closed-loop reasoning 
ensures continuous autonomous operation without requiring human intervention, embodying 
true multi-agent intelligence.
